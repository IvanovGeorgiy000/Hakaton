# СтройКонтроль

Сервис поиска отклонений на строительных площадках по видео с камер (ЛЦТ 2026, задача Департамента градостроительной
политики Москвы, команда «Работяги»): видео камеры → кадр каждые 2 секунды → техника на кадре → сверка с календарным
планом → понятное предупреждение.

## Запуск

**Docker (всё сразу: PostgreSQL, шлюз видео, API, интерфейс):**

```bash
docker compose up --build        # интерфейс: http://localhost:8080 · API и Swagger: http://localhost:8100/docs
```

**Локально (три терминала):**

```bash
cd backend && uv sync && uv run uvicorn app.main:app --port 8100
```

```bash
bash tools/video-gateway.sh      # шлюз видео mediamtx (brew install mediamtx): RTSP с камер → WebRTC в браузер
```

```bash
cd frontend && npm install && npm run dev     # http://localhost:5180
```

Вход: кнопки быстрого входа по ролям на первом экране (демо-режим) или логин `prorab` / `rukovoditel` / `inspektor` / `admin`
с паролем стенда (`SK_DEMO_PASSWORD`, по умолчанию `demo`). Вход через Keycloak — см. [backend/README.md](backend/README.md#вход-через-keycloak-необязательно).

## Как это устроено

```
камера (RTSP) ──► шлюз видео ──► браузер: живое видео (WebRTC), клик по камере — на всю вкладку
                     │
                     └──► сервер: кадр каждые 2 с ──► сервис анализа (сейчас — заглушка) ──► техника на кадре
                                                                                              │
                          раз в минуту: сверка с правилом этапа по плану ◄──────────────────────┘
                                         └──► предупреждение с кадрами-доказательствами
```

Администратор видит всё, что видят остальные роли, и в разделе «Управление» заводит объекты и их план, камеры по IP,
сотрудников с паролями, правила «этап → техника»; каждое такое действие попадает в журнал действий.
