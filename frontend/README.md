# СтройКонтроль — интерфейс

Веб-интерфейс сервиса мониторинга строительных площадок по видео с камер (ЛЦТ 2026, команда «Работяги»).
Все данные приходят с бэкенда ([../backend](../backend/README.md)); в самом интерфейсе остались только подписи и цвета.

## Запуск

Сначала запустите бэкенд (порт 8100) и шлюз видео (`bash ../tools/video-gateway.sh`), затем:

```bash
npm install
npm run dev        # http://localhost:5180 — запросы /api и /media проксируются на http://localhost:8100
npm run build      # сборка в dist/
npm test           # тесты (Vitest): отставание в днях, разбор адреса камеры, советы по ролям, статус плитки видео
npm run gen:api    # типы из схемы API бэкенда → src/api/openapi.d.ts; src/api/contract.ts сверяет с ними data/types.ts при сборке
```

Другой адрес бэкенда для dev-сервера: `VITE_BACKEND_URL=http://host:8100 npm run dev`.
Если интерфейс и API живут на разных доменах — соберите с `VITE_API_URL=https://api.example.ru/api`.
Адрес шлюза видео отдельно задавать не нужно: интерфейс берёт его из `/api/meta` (настройка сервера `SK_VIDEO_WEBRTC_URL`).

## Роли

Экран входа: логин и пароль либо быстрый вход по роли одним нажатием (кнопки видны, когда сервер в демо-режиме).
Если на сервере включён Keycloak (см. [backend/README](../backend/README.md#вход-через-keycloak-необязательно)), вместо формы —
кнопка «Войти через Keycloak»; режим интерфейс узнаёт из `/api/meta` сам.
Права проверяет сервер, интерфейс только прячет лишнее.

| Роль | Разделы | Что может |
|---|---|---|
| **Прораб** | Сегодня · Камеры · План — только свой объект | Ответить на предупреждение: «Техника едет», «Подтверждаю проблему», «Это ошибка», «Устранено»; отметить, сколько работ сделано по факту |
| **Руководитель проекта** | Объекты · Камеры · Отклонения · Отчёты | Подтвердить / закрыть отклонение, проверить своё фото по правилам этапа, добавить объект и настроить его план и зоны, подключить камеру, отметить выполнение работ |
| **Инспектор** | Нарушения · Камеры · Отчёты | Выдать предписание, закрыть нарушение, выгрузить CSV |
| **Администратор** | Объекты · Камеры · Отклонения · Отчёты · Управление | Всё, что остальные роли. Объекты добавляет в их списке, меняет план, зоны и удаляет — на странице объекта; камеры добавляет, меняет и удаляет в разделе «Камеры». В «Управлении» — сотрудники и пароли, правила «этап → техника», журнал действий |

Страница `/demo` работает без входа: минимум по ТЗ на одном экране (фото → техника → этап → отклонения).

## Видео с камер

- **Видеостена** (раздел «Камеры» и вкладка «Камеры» объекта): все камеры сразу показывают живое видео — WebRTC через шлюз
  mediamtx, задержка около полусекунды. Браузер не умеет RTSP, поэтому видео камеры идёт через шлюз, а не напрямую.
  Подключаются только плитки, видимые на экране; когда вкладка браузера скрыта, видео на паузе.
- **Клик по камере — просмотр на всю вкладку** (без полноэкранного режима браузера). Стрелки ← / → переключают
  соседние камеры, Esc — выход.
- **Рамки техники** поверх видео. Если подключён сервис разметки (детектор + трекер), рамки приходят 10–15 раз в секунду
  по WebSocket `/api/tracks` и плавно едут за техникой по номеру трека (`lib/useTracks.ts`, `video/TrackBoxes`);
  видео при этом придерживается на ~150 мс, чтобы рамка попадала в машину. Без сервиса — то, что анализ видит
  на последнем кадре (`/api/live`, опрос раз в 2 секунды). Имитация сервиса для стенда — `backend/app/mock_tracker.py`.
  Рамки выключаются переключателем над стеной, выбор запоминается.
- **Добавление камеры** (руководитель проекта и администратор): производитель → IP, логин, пароль → «Проверить и показать видео» — форма показывает
  живое видео с камеры ещё до сохранения. Для стенда есть быстрая настройка на демо-ролики.

## Оформление

Светлая и тёмная темы плюс режим «как на устройстве» (по умолчанию). Переключатель — значок в верхней панели и на экране входа.
Цвета в компонентах задаются только токенами из `src/index.css`, тёмная тема — переопределение тех же токенов.

## Что показывает интерфейс (по ТЗ)

- **Обнаружение техники** — рамки с типом и уверенностью поверх живого видео (`video/TrackBoxes` — от сервиса разметки, иначе `video/DetectionBoxes`) и на кадрах-доказательствах (`CameraFrame`, `AnalyzeView`).
- **Сопоставление с графиком** — «нужно по плану / видим на камерах» (`EquipmentCheck`, считает сервер) и календарный план
  (`StageTimeline`): завершённые, текущие и будущие этапы; у текущих на полосе — сколько сделано по факту и где работы
  должны быть по графику на сегодня, отставание в днях, нужная техника. Отставание одинаково считается у работы, этапа
  и всего объекта (`lib/schedule.ts`): то, что сделано сейчас, по графику должно было быть готово N дней назад.
- **Выявление отклонений** — карточка с кадрами-доказательствами, блоком «Почему система так решила»
  (план → правило → кадры → вывод), подсказкой «Что делать» и кнопкой «Смотреть камеру сейчас» (`AlertDetail`).
- **Живые данные** — видео в реальном времени, рамки 10–15 раз в секунду от сервиса разметки (без него — раз в 2 секунды),
  предупреждения подтягиваются каждые 20 секунд;
  сверку с планом сервер делает сам раз в минуту.

## Структура

```
src/
  api/          клиент API: адреса, токен (в том числе продление токена Keycloak), ошибки понятными словами;
                openapi.d.ts — типы из схемы бэкенда (npm run gen:api), contract.ts сверяет с ними data/types.ts
  store/        состояние приложения: вход, данные с сервера (TanStack Query), действия
  data/         типы (совпадают с JSON бэкенда), подписи ролей, названия и цвета техники
  components/   video/ (VideoWall, VideoTile, CameraViewer, TrackBoxes/LiveBoxes, DetectionBoxes),
                camera/ (добавить, изменить камеру, адрес потока, проверка связи), site/ (объект, план, зоны, удаление),
                AlertCard, AlertDetail, PrescribeDialog, CameraFrame, EquipmentCheck, StageTimeline, AnalyzeView,
                ErrorBoundary, ui/* (в том числе ActionMenu — меню «⋯»)
  pages/        экраны по ролям: foreman/, manager/, inspector/, admin/ (Manage — Сотрудники, Правила, Журнал),
                shared/ + Login, MinimalDemo, Help
  lib/          видео (WHEP, видимость плиток), рамки в реальном времени (useTracks), опрос /api/live, отставание в днях
                (schedule), советы по ролям (alertAdvice), состояние в адресе (useUrlState), даты по Москве, подписи
  test/         заготовки данных для тестов (*.test.ts лежат рядом с кодом, npm test)
```
