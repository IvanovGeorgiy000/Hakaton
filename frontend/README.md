# СтройКонтроль — интерфейс

Веб-интерфейс сервиса мониторинга строительных площадок по камерам (ЛЦТ 2026, команда «Работяги»).
Все данные приходят с бэкенда ([../backend](../backend/README.md)); в самом интерфейсе остались только подписи и цвета.

## Запуск

Сначала запустите бэкенд (порт 8100), затем:

```bash
npm install
npm run dev        # http://localhost:5180 — запросы /api и /media проксируются на http://localhost:8100
npm run build      # сборка в dist/
```

Другой адрес бэкенда для dev-сервера: `VITE_BACKEND_URL=http://host:8100 npm run dev`.
Если интерфейс и API живут на разных доменах — соберите с `VITE_API_URL=https://api.example.ru/api`.

## Роли

Экран входа: логин и пароль либо быстрый вход по роли одним нажатием (кнопки видны, когда сервер в демо-режиме).
Права проверяет сервер, интерфейс только прячет лишнее.

| Роль | Что видит | Что может |
|---|---|---|
| **Прораб** | Только свой объект: «светофор», этап, предупреждения, камеры, план | Ответить: «Техника едет», «Подтверждаю проблему», «Это ошибка», «Устранено»; запустить проверку «сейчас» |
| **Руководитель проекта** | Все объекты, лента отклонений, любой объект в деталях | Подтвердить / закрыть отклонение, проверить своё фото по правилам этапа |
| **Инспектор** | Журнал нарушений, отчёт за неделю | Выдать предписание, закрыть нарушение, выгрузить CSV |
| **Администратор** | Правила «этап → техника», камеры, сотрудники | Менять правила кнопками «+ / −», **добавлять камеры по IP**, включать, проверять связь, удалять |

Страница `/demo` работает без входа: минимум по ТЗ на одном экране (снимок → техника → этап → отклонения).

## Что показывает интерфейс (по ТЗ)

- **Обнаружение техники** — рамки с типом и уверенностью на кадрах (`CameraFrame`, `AnalyzeView`).
- **Сопоставление с графиком** — «нужно по плану / видим на камерах» (`EquipmentCheck`, считает сервер) и календарный план
  с нужной техникой на каждом этапе (`StageTimeline`).
- **Выявление отклонений** — карточка с кадрами-доказательствами, блоком «Почему система так решила»
  (план → правило → снимки → вывод) и подсказкой «Что делать» (`AlertDetail`).
- **Живые данные** — свежие снимки и предупреждения подтягиваются каждые 20 секунд; «Проверить сейчас» запускает проверку на сервере.

## Структура

```
src/
  api/          клиент API: адреса, токен, ошибки понятными словами
  store/        состояние приложения: вход, данные с сервера (TanStack Query), действия
  data/         типы (совпадают с JSON бэкенда), подписи ролей, названия и цвета техники
  components/   CameraFrame, AlertCard, AlertDetail, EquipmentCheck, StageTimeline, CamerasGrid,
                AddCameraDialog, AnalyzeView, ui/*
  pages/        экраны по ролям: foreman/, manager/, inspector/, admin/ + Login, MinimalDemo, Help
  lib/          утилиты: форматирование дат по Москве, подписи статусов
```

## Стек

lucide-react · react-router · Golos Text (self-hosted). Дизайн-решения: `../design-system/stroymonitor/pages/app.md`.
